# CDAS Next 界面系统主规范

状态：UI-201；2026-08-20。此文件是教师与学生工作台的共同视觉和交互合同。

## 视觉与内容原则

- **命题：** 安静、可信、清楚的 K12 教学操作工作台。参考 Google Classroom 的角色工作台与 Canvas 的任务、反馈、确认范式；不复制其品牌或业务代码。
- 页面从当前位置、状态、任务和一个主操作开始；工作页面不使用营销 hero、杂志式排版或装饰性动画。
- 系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`。不用 Georgia 或大衬线字体。
- 仅使用白、浅灰工作面与海军蓝主操作色；黄色、绿色、红色只表达明确状态，并始终附状态文字。
- 卡片只表示可点击的独立对象；普通分区使用标题、列表与分隔线。禁止渐变、玻璃拟态、粘土风、emoji 图标和装饰性圆形字母头像。

## Token

| 类别 | Token | 值 / 用途 |
|---|---|---|
| 工作面 | `--surface-page`, `--surface` | `#f7f8fa`, `#ffffff` |
| 文本 | `--text`, `--text-secondary` | `#172033`, `#526075` |
| 边界 | `--border`, `--border-strong` | `#dbe1ea`, `#aeb9c8` |
| 主操作 | `--primary`, `--primary-hover` | `#174ea6`, `#123c82` |
| 状态 | `--success`, `--warning`, `--danger` | `#16794c`, `#9a5a00`, `#b42318` |
| 形状 | `--radius-sm`, `--radius-md` | `6px`, `10px` |
| 阴影 | `--shadow-overlay` | `0 16px 48px rgb(23 32 51 / 20%)`，仅弹层 |
| 动效 | `--motion-fast` | `160ms ease`；仅 hover、focus、抽屉和弹层 |
| 层级 | `--z-nav`, `--z-overlay` | `20`, `100` |

间距以 4px 为基准：4、8、12、16、20、24、32、40、48、64。桌面主内容最大宽度 1200px，常规页边距 32px；平板 24px；手机 16px。

## 字体与内容密度

- 正文：16px / 1.55；辅助文字原则上 14px / 1.5，产品正文绝不小于 12px。
- 页面 `h1`：28–32px / 1.25，`h2`：20–24px，`h3`：16–18px。
- 标签：14px，字重 600；避免全大写、过宽字距和纯数字装饰编号。
- 时间、状态和责任主体需显式文字，不依赖颜色或图标。

## 页面结构与响应式

- 桌面（>=1024px）：左侧稳定导航（248px）+ 顶部工具栏（64px）+ 主内容。
- 平板（768–1023px）：紧凑侧栏（可保留文字导航）+ 主内容；列表优先两列信息。
- 手机（<768px）：顶部栏 + 可访问导航抽屉；不保留挤压内容的固定侧栏。内容单列，所有主操作全宽或至少 44px 高。
- 提供跳到主内容链接；路由、标题和 Tab 顺序要一致。390/768/1440 不得产生页面横向滚动。

## 控件合同

| 控件 | 规则 |
|---|---|
| 主按钮 | 最小高度 44px，海军蓝实底白字；每页最多一个明确主操作。|
| 次按钮 | 44px，白底描边；危险操作使用危险文字和边界，不能伪装成主操作。|
| 链接 | 文字明确描述去向；导航项包含文字标签。|
| 输入 | 可见 `label`、辅助说明与就近错误；输入框至少 44px；错误保留用户输入。|
| 状态标签 | 文本 + 轻色背景，状态必须可脱离颜色理解。|
| 可点击对象 | 只对独立活动/提交使用对象卡或整行链接；hover 不移动布局。|

## 提示、空状态与确认

| 场景 | 使用方式 |
|---|---|
| 输入错误 | 字段下 inline error（`role=alert`），不清空输入。|
| 一般说明/只读限制 | 页面内 `Alert`/callout。|
| 空数据 | `EmptyState`：说明原因、真实下一步和相关链接；不用空白区域。|
| 异步成功 | 不抢焦点的 `aria-live=polite` toast/status；按钮显示 pending。|
| 异步失败 | 就近显示可恢复错误，保留表单与选择。|
| 发布、关闭、最终反馈、正式提交 | `ConfirmDialog`：明确标题、影响说明、取消、确认。它只承接 UI 确认；不得缩短 ActionIntent 的准备→确认→执行业务链。|
| 详情或筛选 | 可使用 Sheet / 路由；不要把页面导航塞进弹窗。|
| 无权限/未绑定 | 全页结果，说明未读取或未展示原因，提供登录、退出或本机测试入口。|

## 可访问性与反模式

- 文本对比度至少 AA（普通文本 4.5:1），`focus-visible` 2–4px 清晰可见；`prefers-reduced-motion` 时取消过渡。
- 原生 button、link、label、dialog 优先；不自建 focus trap。对话框可 Esc 和取消退出，并把焦点交回触发器。
- 不做任何装饰性入场/滚动动画，不让 hover 成为唯一交互，不创建假链接或未实现的路由。
- 不引入重量级 UI 库，除非通过 Next 16 + React 19 SSR spike。UI-201 的 `@instructure/ui-buttons@11.7.4` 安装在受限 supply-chain 验证阶段无法完成，因此使用原生语义控件加共享 token 作为后备；不使用私有 API 或 `any`。
